# 확정 구조 안에서의 화면 구성

## Input
브리프, 공유 콘텐츠, 선택한 구조·방향·미디어 정책, 컴파일된 디자인 계약과 플랫폼 규칙.

## Method
- 코드 작성 전에 핵심 과업, 첫 화면의 중심, 주요 행동과 보조 행동을 정한다. 이미 확정된 섹션 순서·내비게이션·밀도는 다시 설계하지 않는다.
- A/B/C의 차이는 허용된 범위의 정보 강조·영역 비율·정렬·타입 위계로 표현한다. 차별화를 위해 필수 콘텐츠를 삭제하거나 새로운 셸을 만들지 않는다.
- 영역 수와 열 수는 선택한 구조를 따른다. 모든 서비스에 같은 히어로·KPI·카드 조합을 강제하지 않는다.
- 제목·본문·메타·CTA의 위계를 계약의 타입 스케일로 구분한다. 같은 종류의 항목은 정보 순서·간격·액션 위치를 일관되게 유지한다.
- 공유 콘텐츠의 이름·수치·상태를 보존한다. 빈 박스나 반복 문구로 화면을 채우지 않는다. 데이터가 부족한 부분을 실제 조회 결과처럼 꾸미지 않는다.
- 이미지가 있으면 피사체와 텍스트·CTA의 영역을 분리한다. no-image 정책에는 이미지나 장식용 대체 히어로를 만들지 않는다.
- 플랫폼 규칙과 계약의 반응형 기준에 맞춰 유연한 폭·줄바꿈·스크롤을 구현한다. 본문을 잘라내어 첫 화면에 억지로 맞추지 않는다.

## Output
설계 과정은 출력하지 않는다. 기존 호출이 요구하는 HTML/CSS 및 응답 형식만 반환한다.

## Guardrails
이 방법론은 토큰 원본이 아니다. 색상·폰트·간격·라운드·상태는 선택된 디자인 계약을 참조하고, 셸·아이콘·플랫폼 불변식은 Aide의 실행 계약을 따른다. 실제 렌더링 전에는 검증 완료라고 주장하지 않는다.
